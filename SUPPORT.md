# Tixkit Support

Choose the path that matches the request:

| Request                                      | Where to go                                                                                                |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Setup, configuration, or operating question  | Search the [public documentation](docs/public) and [troubleshooting guides](docs/public/support.mdx) first |
| Reproducible defect in this repository       | Open a bug report using the repository issue template                                                      |
| Focused product or documentation improvement | Open a feature request or documentation issue                                                              |
| Vulnerability or suspected secret exposure   | Follow [SECURITY.md](SECURITY.md); do not open a public issue                                              |
| General contribution question                | Read [CONTRIBUTING.md](CONTRIBUTING.md), then open a scoped discussion or issue if it remains unanswered   |

## A useful support report

Provide the Tixkit commit or version, runtime and package-manager versions, deployment mode, affected surface, exact reproduction, expected result, observed result, and the smallest sanitized log excerpt that demonstrates the failure. State which validation command fails.

Never post API keys, webhook secrets, provider credentials, database URLs, customer data, private payloads, or complete environment files. Replace identifiers only when doing so preserves the reproduction.

## Scope and response

Public issue support is best effort and does not carry a guaranteed response or resolution time. Maintainers may redirect environment-specific deployment help to the self-hosting runbooks or ask for a minimal reproduction. Roadmap items are not support commitments; see [ROADMAP.md](ROADMAP.md).
