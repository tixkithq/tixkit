Install the core SDK:

```bash
bun add @tixkit/js
```

```ts
import { TixkitClient } from '@tixkit/js';

const tixkit = new TixkitClient({
  apiKey: process.env.TIXKIT_API_KEY,
  apiBaseUrl: process.env.TIXKIT_API_BASE_URL ?? 'http://localhost:4000',
});

const page = await tixkit.events.list({ limit: 10 });
console.log(page.items.map((event) => event.id));
```

The client rejects secret-looking API keys and agent OAuth secrets in a browser runtime. Keep initialization and agent credential exchange in a server process and pass only buyer-safe public data to client components. The package declares API version `2026-08-11`; keep SDK and server compatibility aligned.

Agent-control methods are available under `tixkit.agentControl`. Configure `accessToken` with the authenticated human sponsor's bearer token for those calls; do not pass an API key, and do not give the sponsor token to the agent process. See the [agent Platform API guide](/platform/agent-platform) for the private-beta authorization boundary.

Explicit agent sessions use `tixkit.agentActions`. `prepareContent` submits an event-scoped document to the mutation-free `content.prepare` adapter, while `getContentPreparation` retrieves reauthorized immutable evidence. These methods require Agent OAuth plus the exact capability and delegation; they never apply content or expose an approval/execution path.

`readReport` returns an aggregate-only event sales report for one exact closed UTC range; omit both bounds to use the server-derived event-created-at through observation-time range. `getReport` reauthorizes and recomputes the same range before returning persisted evidence. Grant only `reports.read` with exact event scope and retain sponsor `reports.read`; this direct-only adapter exposes no buyer or attendee identifiers and cannot be planned, approved, executed or exported.

`prepareCampaign` resolves exact published templates, audience eligibility, consent and suppression evidence without queueing email or SMS delivery. `getCampaignPreparation` reauthorizes and recomputes the immutable snapshots before returning persisted evidence. Grant only `campaigns.prepare` with event scope and retain sponsor `messages.write`; this direct-only adapter has no send, approval or execution method.

An explicitly authenticated agent can call `tixkit.agentActions.readEvent` with an event ID, delegation grant ID and idempotency key. The strict version-bound projection excludes buyer, payment, credential and arbitrary metadata fields. Treat the paths declared in `result.untrustedContentPaths` as organizer-authored data, never tool instructions. `getEvent` retrieves the immutable evidence only while the complete current authority intersection remains valid.

An explicitly authenticated agent can call `tixkit.agentActions.readReadiness` with an event ID, a delegation grant ID and an idempotency key. The response requires a durable `result` and `resultSha256` immediately; `getReadiness` retrieves it later while current authority still passes. It is a read-only, direct-only action: do not place it in a plan and do not request approval or execution for it. Exact idempotent replay returns the same action and result evidence after reauthorization; revoked or changed authority fails closed.

Use `tixkit.agentActions.prepareEvent` to validate and normalize a non-status event patch without changing event or media state. `getEventPreparation` retrieves the immutable evidence while current authority and the exact event version remain valid. The response uses a distinct normalized projection type because existing nullable values can differ from request-only change types. Treat every declared `before.<field>` and `after.<field>` path as untrusted organizer-controlled data. This action is direct-only: it cannot enter a plan or consume approval, and a later consequential update must re-resolve and bind the exact current preview.

Use `tixkit.agentActions.prepareEventUpdate` for a consequential update. Review `preview` and `previewSha256`, obtain fresh sponsor approval for the exact `actionDigest` with `approveEventUpdate`, then call `executeEventUpdate` with the immutable approval binding. Use `revokeEventUpdateApproval` before execution and `getEventUpdateExecution` for immutable evidence. Execution re-resolves the proposed patch against the locked current event, rejects version or preview drift, and returns only an exact `updated` result at the next event version. Retry with the same execution key; never rebuild the action after approval.

Organizer memory methods are available under `tixkit.agentMemory`. Every create, inspect, export, correct and remove request requires an idempotency key; correction and removal also require the entry's current version. Memory ownership and provenance are server-derived.

Use resource methods for pagination and typed errors. Supply idempotency options for supported writes and preserve the same logical key across a retry.

Tixkit's internal provider-SDK policy does not deprecate this public SDK. A future version-bound agent integration skill may provide coding agents with the same authentication, idempotency, webhook and contract guidance, but it will be additive and must match the immutable API release. Until that artifact is published and validated, use this SDK, the versioned API reference and contract tests as the supported integration surfaces.
