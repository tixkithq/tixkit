Use repository discussions or the documented support destination for usage questions that contain no private data. Use issue templates for reproducible public defects and documentation problems.

Report security vulnerabilities privately through the process in `SECURITY.md`; never open a public issue containing exploit detail, credentials, tenant data, or customer information.

For an operational incident, follow [incident runbooks](/operations/incidents) and your organization's escalation policy. Public community support is not a production paging service.

Managed Cloud support plans and SLA commitments are not approved or published. Self-Hosted operators choose their own support and escalation arrangements. Self-Hosted support arrangements do not create managed Cloud support or SLA commitments.

When reporting a docs problem, include the canonical page URL, source path, version/commit when known, and the incorrect or missing outcome. Remove secrets, personal data, private topology, and internal payloads.
