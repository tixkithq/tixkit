Deploy immutable artifacts built from one reviewed commit. The API, worker, OpenAPI reference, SDK compatibility statements, dashboard, checkout, and docs must describe the same contract.

Use the [Compact profile](/self-hosting/compact) for a complete supported single-host evaluation or smaller installation. Use the Production profile and externally operated backing services for high availability and independent scaling.

Follow the dedicated [Production profile runbook](/self-hosting/production) for compatibility, sizing, secret, migration, network, observability, and recovery gates.

The Production chart is `infra/helm/tixkit` with `values-production.yaml`. It intentionally refuses placeholder image digests, bundled datastores, unrestricted network CIDRs, automatic migration hooks, missing observability, and incomplete ExternalSecret mappings. Supply release-manifest image digests and environment-specific ingress, database, and service egress ranges; do not weaken these checks with a copied evaluation file.

For External Secrets, reconcile the `ExternalSecret` and wait for its target Secret before running `infra/scripts/run-helm-migration.sh`. The runner validates the chart-derived key inventory, acquires an atomic migration lock, applies the release-scoped database egress policy, creates a uniquely named bounded Job, waits for completion, and prints current logs. It fails rather than reusing a completed Job or overlapping another migration. This local runner evidence does not replace a production-like install, upgrade, rollback, and recovery rehearsal.

## Release order

1. Back up and verify restore readiness.
2. Run the release dry-run and documentation/OSS export gates.
3. Apply forward-compatible migrations using the approved migration identity.
4. Deploy API and worker with compatible Temporal workflow code.
5. Deploy admin, checkout, and docs.
6. Verify health, representative public/authenticated reads, checkout, workflow, webhook, and documentation routes.

## Rollback

Roll back application artifacts independently only while contract and migration compatibility permits it. Prefer a forward fix for destructive schema changes. Preserve documentation redirects so dashboard links remain valid across a docs rollback.

## Smoke checks

Verify `/health` for API and docs, worker readiness, a real published test event, authenticated context, and a test-safe checkout. A green homepage is not a complete deployment proof.

Continue with [observability configuration](/self-hosting/observability) before accepting the release.
