Tixkit runs separate API, Temporal worker, admin, checkout, and documentation processes. PostgreSQL is the primary documented local path; repository validation also covers declared compatible database modes. Redis supports runtime coordination, Temporal owns durable workflows, and S3-compatible storage owns generated/uploaded artifacts.

## Trust boundaries

Expose only required public ingress: buyer checkout/public API, authenticated admin/API, provider webhooks, and documentation. Keep database, Redis, Temporal service, and object-storage administration private.

The API authenticates and scopes requests. The worker consumes trusted Temporal tasks but still calls scoped repositories/providers. Browser applications never receive database, provider, API-key, or signing secrets.

## Failure boundaries

API health does not prove worker readiness; worker health does not prove provider readiness. Monitor each service plus database, Redis, Temporal, storage, authentication, payments, messaging, and webhook delivery independently.
