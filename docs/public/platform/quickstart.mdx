> **Experimental private beta:** hosted Platform API access is not generally available. Use only the environment identifier, API origin, credential flow, and support channel supplied in an invitation. Public examples do not grant access.

## Confirm the invited environment

Sign in through the invitation and verify the expected organization, environment, region, and permissions. Keep sandbox and production credentials separate. If any identifier differs from the invitation, stop before creating a key.

## Create a read-only credential

Create a server-side credential with the narrowest scope needed to list events. Copy its secret once into a secret manager or an ephemeral shell. Never place it in browser code, URLs, screenshots, analytics, support messages, or client-visible environment variables.

Set the exact origin from the invitation; this guide intentionally provides no default hosted origin:

```bash
export TIXKIT_API_BASE_URL='paste-the-exact-invited-api-origin'
printf 'Tixkit API key: ' >&2
IFS= read -r -s TIXKIT_API_KEY
export TIXKIT_API_KEY
printf '\n'
```

Paste the secret only at the silent prompt, then run `unset TIXKIT_API_KEY` when the session ends. The secret must never appear in shell history, command arguments, or a committed environment file.

## Make a read-only request

```bash
curl --fail-with-body --config - <<EOF
header = "Authorization: Bearer $TIXKIT_API_KEY"
url = "$TIXKIT_API_BASE_URL/v1/events"
EOF
```

`--config -` reads the expanded header from standard input, so the secret is not placed in curl's process arguments or a temporary file.

An empty event list is valid. Treat `401` as a credential problem, `403` as a permission or tenant-scope denial, `404` as an environment or path mismatch, and `429` as a signal to honor the supplied retry policy. Do not broaden scopes to bypass a denial.

## Add webhook verification

Create a test endpoint, store its signing secret separately from the API key, [verify signatures before parsing](/developers/webhooks/verify-signatures), reject stale timestamps, and make processing idempotent. Revoke the credential immediately if it appeared in client code or logs.
