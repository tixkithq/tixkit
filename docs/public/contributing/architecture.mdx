The Bun/Turbo workspace contains runtime applications under `apps/` and reusable or service packages under `packages/`.

## Runtime applications

`apps/admin-dashboard` is the authenticated operator UI. `apps/checkout` is buyer-facing checkout/public event behavior. `apps/docs` builds this documentation. SDK demo apps are executable contract fixtures.

## Backend boundaries

`packages/domain` owns pure rules and types. `packages/db` owns Kysely repositories/migrations. `packages/api` owns Fastify routes, auth, permissions, and serialization. `packages/workflows` owns Temporal workflows/activities. `packages/openapi` owns the public HTTP schema.

## Outbound provider boundary

Provider operations cross Tixkit-owned adapters. Routes, activities, and feature modules do not instantiate vendor clients or call provider endpoints directly. The internal provider-client boundary owns deadlines, idempotency propagation, explicit API versions, error and retry classification, bounded redacted diagnostics, and dependency telemetry; business policy, persistence, reconciliation, consent, and workflow retries remain with their owning packages.

Vendor SDKs may remain inside an adapter when they implement a meaningful browser, security, signing, protocol, workflow-runtime, or instrumentation boundary. This rule concerns upstream dependencies and does not change the public Tixkit SDKs offered to integrators. The accepted decision and migration scope are recorded in `docs/internal/architecture/outbound-provider-clients.md`.

## Frontend and integration packages

Content packages own shared editors/rendering; `admin-table-core` owns reusable table behavior; SDK and widget packages expose public integration surfaces. `packages/docs-core` owns documentation route/help/readiness/search contracts without importing applications.

## Repository boundary

The accepted target makes the public `tixkit/tixkit` repository authoritative for shared product code, public integrations, documentation, and the complete Self-Hosted runtime. The private `tixkit/tixkit-cloud` repository consumes immutable public releases and contains proprietary Cloud operations, managed integrations, and natural-language agent orchestration. Public source and CI never depend on private source.

During the C-130 cutover, `scripts/export-oss.mjs` remains a temporary extraction and leak-validation tool. It is not the long-term publication architecture.
