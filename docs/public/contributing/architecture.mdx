The Bun/Turbo workspace contains runtime applications under `apps/` and reusable or service packages under `packages/`.

## Runtime applications

`apps/admin-dashboard` is the authenticated operator UI. `apps/checkout` is buyer-facing checkout/public event behavior. `apps/docs` builds this documentation. SDK demo apps are executable contract fixtures.

## Backend boundaries

`packages/domain` owns pure rules and types. `packages/db` owns Kysely repositories/migrations. `packages/api` owns Fastify routes, auth, permissions, and serialization. `packages/workflows` owns Temporal workflows/activities. `packages/openapi` owns the public HTTP schema.

## Outbound provider boundary

Provider operations cross Tixkit-owned adapters. Routes, activities, and feature modules do not instantiate vendor clients or call provider endpoints directly. The internal provider-client boundary owns deadlines, idempotency propagation, explicit API versions, error and retry classification, bounded redacted diagnostics, and dependency telemetry; business policy, persistence, reconciliation, consent, and workflow retries remain with their owning packages.

Vendor integrations are classified as direct HTTP, a contained SDK, or a runtime/security SDK boundary. Vendor SDKs may remain inside an adapter when they materially reduce browser, security, signing, protocol, workflow-runtime, or instrumentation risk. Stripe's server SDK currently remains contained behind `StripeGateway`; direct REST is not presumed safer and requires complete protocol/provider parity plus a measured operational benefit before migration.

The provider registry and validator must reject unclassified hosts, imports and production dependencies. Test-only vendor SDKs do not belong in production dependency sets. This rule concerns upstream dependencies and does not change the public Tixkit SDKs offered to integrators. The executable boundary lives in `packages/provider-clients`, its package tests, and the public dependency-validation scripts.

## Frontend and integration packages

Content packages own shared editors/rendering; `admin-table-core` owns reusable table behavior; SDK and widget packages expose public integration surfaces. `packages/docs-core` owns documentation route/help/readiness/search contracts without importing applications.

## Repository boundary

The public `tixkithq/tixkit` repository is authoritative for shared product code, public integrations, documentation, and the complete Self-Hosted runtime. The private `tixkithq/tixkit-cloud` repository consumes immutable public releases and contains proprietary Cloud operations, managed integrations, and natural-language agent orchestration. Public source and CI never depend on private source.

This public repository is the release source. Boundary-validation scripts may still inspect release contents for accidental private dependencies, but they are safety checks rather than a publication path.
