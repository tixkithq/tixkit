Event pages use one hard-cutover contract. Schema v2 is Puck-only content and uses `@puckeditor/core` terminology: `Config`, `Data`, root props, `content`, `zones`, `<Puck>`, and `<Render>`.

## Shared imports

- Use `@tixkit/content-event-page/puck` for the server-safe contract, validation guards, migration signatures, and Puck data aliases.
- Use `@tixkit/content-event-page-react/puck` for the React-side Puck configuration and render wrapper.

`EventPageDocumentV2` stores canonical Puck data at `editor.data` with `editor.provider: "@puckeditor/core"`. It never stores the former TipTap `editor.document`, typed `blocks[]` store, server-rendered HTML, headless blocks, or a `renderModel`.

## Public payload

Public checkout consumes `PublicEventPagePayloadV2.page.puckData`. The payload keeps document and version metadata, discovery data, settings, and the shared validation shape.

The following former runtime fields are not part of the v2 payload:

- `page.html`;
- `page.text`;
- `page.headless`;
- `page.renderModel`;
- `version.renderedHtml`;
- `version.renderedText`; and
- public `contentJson`.

## Responsibility boundary

- Checkout Form remains the checkout data-collection editor.
- Event Page owns the complete Puck page composition, including editable header, ticket, product add-on, resale, checkout CTA, and footer blocks.
- Public checkout supplies live runtime data and interaction handlers to those blocks. It does not inject a second visual chrome outside the Puck document.

## Event media references

The editor stores event-owned poster, cover, and social selections as portable, event-relative references:

- `tixkit:event-media:poster`
- `tixkit:event-media:cover`
- `tixkit:event-media:social`

References contain no tenant, event, rendition, host, artifact, or credential identifier. They are valid only in image-bearing event-page fields: root and discovery cover/social images, plus the top-level `imageUrl` of `EventHeader`, `EventDescription`, and `Media`. General links, logos, speakers, sponsors, and buttons continue to require safe URLs and reject media references.

Organizer previews fetch the authenticated `page` rendition and use a short-lived object URL in memory. Saved documents retain the logical reference. Public reads resolve a copy of the published document to the exact selected role and surface (`page` or `social`) without rewriting the stored version. Publishing fails closed when the selected asset or required rendition is unavailable.

Portable bundles preserve logical references inside versioned content documents. Import rebinding therefore resolves them against destination-owned event media; private upload identifiers, signed URLs, and preview object URLs never cross the boundary.

## Component identifiers

The v2 guards accept canonical PascalCase component types such as `EventHeader`, `Tickets`, `ProductAddOns`, `ResaleTickets`, `CheckoutCta`, and `BrandFooter`.

Legacy snake_case commerce types such as `event_header`, `tickets`, `products`, `resale_tickets`, and `brand_footer` must fail validation after migration.

Any schema or payload change requires migration coverage, admin and checkout rendering parity tests, generated contract updates, and a documented compatibility transition.
