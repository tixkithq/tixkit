API version `2026-08-11` adds explicit `400` and `503` response contracts to `POST /webhooks/stripe`. The webhook request and successful response are unchanged.

Malformed bodies, missing signatures, invalid signatures, and invalid verified envelopes return the standard `ApiError` shape with a stable code, message, and request ID. A checkout workflow signal failure returns the same envelope with `503`, allowing Stripe to retry without treating the provider event as processed.

Clients should use the HTTP status and `error.code` for control flow and retain `error.requestId` for support correlation. Error messages are descriptive but are not a machine-readable contract. Signature material, provider diagnostics, secrets, and buyer data are never returned.

This additive contract change requires no database migration. Immutable `2026-08-10` artifacts remain unchanged.
