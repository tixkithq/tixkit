API `2026-08-19` restricts the `Idempotency-Key` header on `POST /events/{eventId}/messages` to a safe token between 1 and 255 characters. The first character must be alphanumeric. Every remaining character must be alphanumeric or one of `.`, `_`, `:`, or `-`.

Valid examples include `campaign-42`, `release_2026.08.19`, and `tenant:campaign:attempt-1`. Keys containing spaces, slashes, control characters or other punctuation are invalid. Empty values and values longer than 255 characters are also invalid. Requests that do not satisfy the contract return `400` before campaign persistence, provider activity or workflow dispatch.

This is intentionally breaking because earlier releases accepted some whitespace, punctuation and oversized values. Generate a stable token before sending the request; do not trim or otherwise rewrite an invalid value after an ambiguous response.

Retry the same event and byte-equivalent request intent with the same key. Do not reuse a key for a different event, audience, message content or campaign configuration. Tixkit binds idempotent replay to the original request intent and rejects conflicting reuse.
