API version `2026-08-14` makes the generic attendee update operation profile-only so lifecycle mutations cannot bypass the canonical check-in, refund, or transfer invariants.

## Remove attendee lifecycle updates from profile patches

`PATCH /v1/attendees/{attendeeId}` now accepts only `firstName`, `lastName`, `email`, and `phone`. Remove `status` from this request in custom clients and regenerate clients from the `2026-08-14` OpenAPI contract.

Generic attendee profile updates cannot check in, revoke, refund, cancel, or transfer a ticket. Use the dedicated check-in scan and offline-sync operations for check-in lifecycle changes; those operations preserve ticket validation, list and device scope, idempotency, scan logs, and check-in activity. Use the dedicated refund and transfer workflows for those lifecycle changes.
