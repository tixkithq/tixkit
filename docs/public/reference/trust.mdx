## How to read the states

- `published` means the named public policy exists now.
- `locally-proven` means the listed command and repository artifacts prove a bounded local contract.
- `pending-policy-decision` means product, operational, privacy, security or legal owners must approve a commitment; no target is implied.
- `pending-external-proof` means an independent or hosted party must produce evidence.
- `not-yet-offered` means the managed service surface does not exist publicly.

Self-Hosted operators choose their infrastructure location, incident communication, vendors and support arrangements. That control does not establish a managed Cloud residency promise, subprocessor list, status history or SLA. Do not infer certifications, uptime targets, recovery objectives, regions or assessment results from planned workflows.

## Verify release material

For an approved API release, follow the exact checksum, GitHub attestation, registry-integrity and clean consumer-install procedure in [the API release train](/reference/api-release-train). Public artifact workflows also require SPDX SBOMs and provenance attestations, but those workflow contracts are not a public release receipt until the protected hosted run succeeds.
