## How to read the states

- `published` means the named public policy exists now.
- `locally-proven` means the listed command and repository artifacts prove a bounded local contract.
- `pending-policy-decision` means product, operational, privacy, security or legal owners must approve a commitment; no target is implied.
- `pending-external-proof` means an independent or hosted party must produce evidence.
- `not-yet-offered` means the managed service surface does not exist publicly.

Self-Hosted operators choose their infrastructure location, incident communication, vendors and support arrangements. That control does not establish a managed Cloud residency promise, subprocessor list, status history or SLA. Do not infer certifications, uptime targets, recovery objectives, regions or assessment results from planned workflows.

## Verify hosted DR evidence

No hosted production DR receipt or trusted public keyring is currently published. The dedicated consumer verifies the signed proof, checksum, reviewed expectations, exact evidence bytes, authoritative Git revision, workflow tuple, hosted signature, and observation timing together:

```bash
node scripts/verify-hosted-production-dr.mjs \
  --evidence /absolute/path/to/evidence.json \
  --signature /absolute/path/to/evidence.json.sig \
  --checksum /absolute/path/to/evidence.json.sha256 \
  --public-key /absolute/path/to/proof-public-key.pem \
  --expectations /absolute/path/to/rehearsal-expectations.json \
  --receipt /absolute/path/to/hosted-dr-receipt.json \
  --trusted-keyring /absolute/path/to/authenticated-hosted-keyring.json
```

The result is only `eligibleForReview`. The protected producer has not run, and no authenticated keyring, hosted receipt, durable rehearsal artifact or complete drill matrix exists, so no production DR result is claimed.

## Verify a policy publication decision

Policy commitments cannot move from `pending-policy-decision` to `published` based on edited prose or a single signer. A proposed trust-program snapshot requires a separate, independently authenticated policy keyring and a receipt signed by the exact role quorum for that policy:

```bash
node scripts/validate-policy-promotion.mjs \
  --current-program /absolute/path/to/current-trust-program.json \
  --proposed-program /absolute/path/to/proposed-trust-program.json \
  --receipt /absolute/path/to/policy-approval-receipt.json \
  --trusted-keyring /absolute/path/to/authenticated-policy-keyring.json \
  --repository-root /absolute/path/to/tixkit
```

The verifier binds one exact pending-to-published record transition, the authoritative Git commit and tree, the proposed public policy artifacts, the active decision version, its independently registered monotonic publication time, and distinct role-scoped Ed25519 signatures valid at both decision and publication. It returns only `eligibleForPublication` and never edits or promotes the canonical registry. A keyring delivered with the receipt is not an independent trust root. No policy approval receipt or trusted policy keyring is currently published, and every pending policy remains pending.

## Verify release material

For an approved API release, follow the exact checksum, GitHub attestation, registry-integrity and clean consumer-install procedure in [the API release train](/reference/api-release-train). Public artifact workflows also require SPDX SBOMs and provenance attestations, but those workflow contracts are not a public release receipt until the protected hosted run succeeds.
