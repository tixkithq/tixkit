Use the exact HTTPS API origin assigned to your environment, followed by the documented `/v1` prefix. Hosted private-beta invitations supply this origin; public documentation intentionally provides no default hosted hostname.

## Request model

Send and accept JSON unless an operation documents a file response. Authenticated routes accept a Clerk bearer token, API key, or supported device credential according to the operation. Public buyer routes explicitly omit authentication.

Every authenticated resource read is still tenant-, organization-, brand-, or event-scoped. Knowing an identifier is not sufficient authorization.

## Integration rules

- Keep secret API keys in a server secret store and send them only in the `Authorization` header.
- Use cursor pagination instead of guessing offsets.
- Preserve `requestId` from error responses for diagnosis, but never log credentials or payloads containing personal data.
- Supply a unique idempotency key for a mutation that moves money, inventory, tickets, messages, or durable work.
- Retry only according to the returned status and documented operation behavior.
