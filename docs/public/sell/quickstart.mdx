> **Experimental private beta:** Tixkit Cloud organizer access is not generally available. An invitation provides the sign-in address, workspace, region, test-payment policy, and support channel. Do not infer availability or create credentials from examples in public documentation.

## Accept the invited workspace

Open the exact invitation link and confirm the expected workspace and organization before accepting. Use your own named identity; do not share an account. If the workspace, region, or role is unexpected, stop and contact the invitation's support channel.

## Create a test event

Open **Events**, choose **Create event**, and use test-safe content. Add a future occurrence, one ticket type with available inventory, a sales window that includes the current time, and the required checkout fields. Preview the buyer page before publishing.

Follow [Create and publish the first event](/getting-started/first-event) for the complete readiness checks. The dashboard must show the event as ready; do not repeatedly publish around an unresolved schedule, inventory, permission, or checkout-form error.

## Complete a test order

Use the payment mode assigned to the invited test environment. Never enter a live card or personal buyer data unless the invitation explicitly identifies an authorized production environment. Complete [the test checkout journey](/getting-started/test-checkout), then confirm the order, attendee, inventory change, and receipt state in the organizer dashboard.

## Prepare event day

Review team permissions, refund policy, check-in devices, connectivity fallback, incident ownership, and a representative test scan. Managed organizer agents remain a separate planned private beta and are not required for this journey.
