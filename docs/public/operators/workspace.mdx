Tixkit scopes operational data by tenant, organization, and brand. Always confirm the active context before creating an event, connecting a provider, or inviting a teammate.

## Confirm the selected context

Use the organization and brand selectors in the authenticated dashboard shell. After changing context, wait for the scoped bootstrap data to reload. The event, payment, developer, and reporting views must reflect the new selection before you continue.

## Update workspace identity

Open **Settings → Workspace**. Review the display identity and any organization settings available to your permission set. Save once, then reload the page to verify the API persisted the value.

Users without settings permission may read permitted workspace context but must not be shown a change action. Ask a workspace owner to make the change rather than sharing credentials.

## Diagnose a context mismatch

- If expected events or orders disappear, recheck the selected organization and brand.
- If an action returns forbidden, confirm both the active context and your permission.
- If the selector offers an unexpected tenant, stop and report the isolation issue without copying customer data into the report.

Continue with [brand configuration](/operators/brands) or [team access](/operators/team-and-permissions).
