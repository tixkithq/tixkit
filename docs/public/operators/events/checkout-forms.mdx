Checkout forms can collect buyer-level and attendee-level answers. Minimize personal data and make required fields and consent language explicit.

## Review the form

Open the event checkout-form view. For each field, confirm its audience, requirement state, label, and purpose. Use attendee fields only when the answer must differ per admission; use buyer fields for order-level contact or agreement.

Do not request credentials, payment-card data, government identifiers, or unrelated sensitive information in custom fields.

## Save and preview

Save the form revision, then open checkout preview. Add more than one ticket when validating attendee-level behavior. Confirm required validation, accessible labels, error text, consent presentation, and the final order summary.

## Diagnose stale behavior

If checkout shows an older form, verify the correct event and brand, the saved/public revision, and whether an existing checkout session captured an earlier revision. Start a new private session before assuming the save failed.

Complete a [test checkout](/getting-started/test-checkout) after every material form or consent change.
